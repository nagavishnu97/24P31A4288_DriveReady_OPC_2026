01Chatbot vs agent

A chatbot answers with words. An agent is given a goal and takes actions until the goal is done.

Ask a chatbot "Cancel my order" and it tells you how to cancel. Ask an agent and it cancels it: it looks up the order, calls the cancel system, checks it worked and then tells you. The difference is not a smarter model; it's that the agent is allowed to use tools and decides the steps itself.

Real world

Many food-delivery and banking apps started with chatbots that only explained policies. Newer assistants can actually check your order status, start a refund or block a card, because they are connected to the company's systems. That connection is what makes them agents.

Analogy

A receptionist tells you which counter books train tickets. A personal assistant books the ticket, checks the PNR and sends it to you. Same knowledge; only one of them does the work.

03The agent loop: think → act → observe → repeat

An agent works in a loop: decide the next step, do it, look at the result, and repeat until the goal is reached.

This pattern is often called ReAct (Reason + Act). In each round the model either says "I need to use a tool" (act) or "I have the final answer" (stop). Your code runs the tool and hands the result back (observe). The loop ends when the model gives a final answer, or when you stop it after too many rounds.

Watch the loop solve one customer questionLive
Real world

Google Maps works in a loop too: plan a route, drive, see traffic, re-plan. An agent does the same with tools: try, look at the result, adjust. That's why an agent can handle questions nobody wrote exact steps for.

Analogy

Cooking without a fixed recipe. Decide (add salt), act (add it), taste (observe), decide again, until it tastes right. You don't plan every pinch in advance.

05Agent or not? Pick the simplest thing that works

Use an agent only when the steps can't be known in advance. If you can write the steps down, plain code is cheaper, faster and safer.

Agents are exciting, but every extra round of thinking costs time and tokens, and more freedom means more ways to go wrong. Engineers ask three questions, in order:

  1. Can I write the exact steps? → write normal code (no AI).
  2. Do I just need text understood or written once? → one LLM call (Level 1).
  3. Must it decide which steps to take, using tools? → an agent.
You decide: plain code, one LLM call, or an agent?Live
Choose for each task.
Real world

Teams that build reliable AI products often start with the simplest option and add agent freedom only where it clearly helps. At Sweet Crumbs, calculating a bill stays plain Python; writing a festival post is one LLM call; handling an unclear customer order is a job for the agent.

Analogy

You don't hire a manager to switch on a fan. Fixed jobs need a switch (code); creative one-off jobs need a writer (one LLM call); only open-ended jobs need someone who plans (an agent).

06Why LangChain?

LangChain is a Python library that gives every model the same simple interface, plus ready-made pieces for prompts, tools, memory and agents.

On Day 1 you wrote the API call yourself with the openai library. That's fine for one call. But agents need tools, loops, memory and the ability to switch models, and writing all of that by hand is slow and easy to get wrong. LangChain provides these as tested building blocks, so you write less code.

# Day 1: raw API call
from openai import OpenAI
client = OpenAI(api_key=KEY,
    base_url="https://api.groq.com/openai/v1")
r = client.chat.completions.create(
    model="openai/gpt-oss-20b",
    messages=[{"role": "user",
               "content": "Eggless available?"}])
print(r.choices[0].message.content)
# Day 3: the same call with LangChain
from langchain_groq import ChatGroq
llm = ChatGroq(model="openai/gpt-oss-20b")


reply = llm.invoke("Eggless available?")
print(reply.content)

Model prices and quality change every few months. A team using LangChain can test a cheaper or better model by changing a line or two, instead of rewriting the app. On Day 10 we use this to give Sweet Crumbs a backup model when Groq is down.

07LangChain basics: model, template, chain

Three pieces you'll use every day: a chat model you call with invoke, a prompt template with blanks to fill, and a chain that joins steps with the | pipe.

① The chat model

llm = ChatGroq(model="openai/gpt-oss-20b", temperature=0.3)
reply = llm.invoke([
    ("system", "You are Sweet Crumbs' assistant. Answer in under 30 words."),
    ("human",  "Do you make eggless cakes?"),
])
print(reply.content)     # the text, like response.choices[0].message.content on Day 1

Messages can be simple (role, text) pairs. LangChain calls the user "human" and the model "ai"; they mean the same as user and assistant.

② The prompt template

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are the assistant for {business}. Answer in under 30 words."),
    ("human",  "{question}"),
])

Words in {curly braces} are blanks, filled when you run it. One template can serve the bakery, a tuition centre or a salon.

③ The chain

from langchain_core.output_parsers import StrOutputParser

chain = prompt | llm | StrOutputParser()     # fill blanks → ask model → keep just the text
answer = chain.invoke({"business": "Sweet Crumbs Home Bakery",
                       "question": "Do you make eggless cakes?"})
print(answer)

The | pipe passes the output of one step into the next, like a conveyor belt. StrOutputParser takes the reply object and keeps just the text.

Fill the template, follow the chainLive
Change the business name to your own and run it again: same template, new assistant.
Common trap

Because { } means "blank" in a template, a system message containing real curly braces (for example JSON) causes an error about a missing variable. Write the menu as plain text lines, or double the braces {{ }}.

Real world

Mail merge in Word or a bulk WhatsApp greeting ("Dear {name}, happy Diwali!") works the same way as a template: one message, many fills. Chains are how bigger apps join steps: fill the prompt, ask the model, clean the answer, save it.

Analogy

A printed form with blanks (the template) moving along a factory conveyor belt (the chain): one station fills the blanks, the next asks the model, the last one wraps up the text.

08Testing your assistant: tests.csv

Write down real customer questions and what a correct answer must contain. Run them all after every change.

Changing one line of a prompt can fix one answer and quietly break another. So we keep a small test file: each row is a question and a word or phrase the answer must include. A loop runs every question and prints PASS or FAIL. The pass rate tells you, in one number, whether a change made things better or worse.

Cell 1 · Setup

import os
from google.colab import userdata
os.environ["GROQ_API_KEY"] = userdata.get("GROQ_API_KEY")   # LangChain reads it from here

from langchain_groq import ChatGroq
llm = ChatGroq(model="openai/gpt-oss-20b", temperature=0.3)

Cell 2 · The assistant: template + memory + chain

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser

SYSTEM = """ROLE:   You are the friendly assistant for Sweet Crumbs Home Bakery.
FACTS:  Plum cake Rs 500. Chocolate cake Rs 650. Cupcake Rs 80 each.
        Orders need 24 hours' notice. All cakes have eggless versions.
RULES:  Never promise a delivery time or place. If it isn't in FACTS,
        say "I'll check with the owner." Work out totals carefully.
FORMAT: Under 50 words, friendly, English or Telugu matching the customer."""

prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM),
    MessagesPlaceholder("history"),          # the chat so far goes here
    ("human", "{question}"),
])
chain = prompt | llm | StrOutputParser()

history = []
def ask(question: str) -> str:
    answer = chain.invoke({"history": history, "question": question})
    history.extend([("human", question), ("ai", answer)])
    return answer

print(ask("Hi, I'm Ravi. Do you make eggless cakes?"))
print(ask("What's my name?"))

Cell 3 · Tests

import csv

def run_tests(path: str = "tests.csv") -> None:
    rows = list(csv.DictReader(open(path)))
    passed = 0
    for row in rows:
        answer = chain.invoke({"history": [], "question": row["question"]})
        ok = row["must_include"].lower() in answer.lower()
        passed += ok
        print("PASS" if ok else "FAIL", "|", row["question"], "→", answer[:70])
    print(f"\n{passed}/{len(rows)} passed ({passed / len(rows):.0%})")

run_tests()      # create tests.csv first with the %%writefile cell from topic 8

Cell 4 · Sneak peek: the same assistant as a LangChain agent

from langchain.agents import create_agent

agent = create_agent(model=llm, tools=[], system_prompt=SYSTEM)   # tools come tomorrow
result = agent.invoke({"messages": [{"role": "user", "content": "Do you make eggless cakes?"}]})
print(result["messages"][-1].content)

With an empty tool list it behaves like the chain above. On Day 4 we pass real tools like get_price, and the agent loop from topic 3 starts working by itself.
